    Customize TerrainGen¶

    Every part of a TerrainGen terrain is an object you can replace with your own. That covers the starting heights, the relief over them and how coarse heights are refined. It covers how many craters there are, how old they are, their shape and how they wear. It also covers where features gather, the albedo and the rocks boulders are made of. Your parts work exactly like the built-in ones. They join the same terrains, are listed and queried the same way, and evaluate over any grid or at single points.

    This guide walks through each kind of part, from combining built-in parts to writing your own, in Python and C++. Every example is run as a test, and every image is made by the code above it. Each step is also a task under Customization.

    To change Subclass Implement
    The starting heights Source the grid it covers and the heights of a block of samples
    The relief over them Layer (FormulaLayer in C++) the height at a point from the height before it
    How posts are refined Upsampler the heights of a block of samples from the posts around them
    How many craters or boulders there are SizeFrequencyDistribution the cumulative count N(>= D)
    How old craters are CraterAgeModel the lifetime by diameter, and optionally how ages are drawn
    The shape of a crater CraterProfile the height by distance from the center, and its reach
    How craters wear DegradationModel each crater's fresh and current depth and rim
    Where craters and boulders gather SurfaceField the value at a point and the largest value
    The starting albedo AlbedoSource the number of bands and the value at a point
    Changes to the albedo AlbedoLayer the value at a point from the value before it
    The shape of a boulder none, a list of meshes the meshes, read with read_mesh

    Compose built-in parts¶

    Before writing anything, many terrains are a matter of combining what is built in. A noise layer adds a stack of fractals, each with its own seed, wavelength, amplitude, octaves and type. Here broad fBm hills come first and finer ridged noise goes on top.

    hills = terraingen.Fractal(seed=1, wavelength=200.0, amplitude=6.0, octaves=4)
ridges = terraingen.Fractal(
    seed=2, wavelength=60.0, amplitude=1.5, octaves=5, type=terraingen.FractalType.RIDGED
)
noise = terraingen.NoiseLayer([hills, ridges])  # added in order
terrain = terraingen.Terrain(source=terraingen.FlatSource(257, 257, 1.0), layers=[noise])
heights = terrain.evaluate()

    Fractal hills = Fractal::Fbm(1, 200.0, 6.0);  // seed, wavelength and amplitude in meters
hills.octaves = 4;
Fractal ridges = Fractal::Fbm(2, 60.0, 1.5);
ridges.type = FractalType::Ridged;
ridges.octaves = 5;

const auto noise = std::make_shared<NoiseLayer>(std::vector<Fractal>{hills, ridges});
const Terrain terrain(Surface{}, std::make_shared<FlatSource>(257, 257, 1.0), {noise});
const Raster<float> heights = terrain.Evaluate();

    Sources¶

    A source gives a terrain's starting heights. It defines the grid it covers and the height at any point and sample spacing. It can be an analytic surface, a DEM in a format of your own or the ground of another simulation. Layers are laid over it as over a GeoTIFF. Here a Gaussian dome takes craters.

    class Dome(terraingen.Source):
    """A Gaussian dome 20 m high and 60 m wide on a 129 x 129 grid of 1 m cells."""

    def grid(self):
        return terraingen.RasterGrid.centered((0.0, 0.0), (129.0, 129.0), 1.0)

    def fill_samples(self, samples, spacing, threads):
        p = samples.positions()
        r2 = p[:, 0] ** 2 + p[:, 1] ** 2
        samples.heights()[:] = 20.0 * np.exp(-r2 / (2.0 * 30.0**2))

craters = terraingen.CraterLayer()
heights = terraingen.Terrain(source=Dome(), layers=[craters]).evaluate()

    // A Gaussian dome 20 m high and 60 m wide on a 129 x 129 grid of 1 m cells.
class Dome final : public Source {
  public:
    RasterGrid Grid() const override {
        return RasterGrid::Centered({0.0, 0.0}, {129.0, 129.0}, 1.0);
    }

  protected:
    void FillSamples(SampleBlock& samples, double /*spacing*/,
                     unsigned /*threads*/) const override {
        for (std::size_t i = 0; i < samples.Size(); ++i) {
            const Vec2d p = samples.Position(i);
            const double r2 = p.x * p.x + p.y * p.y;
            samples.Height(i) = static_cast<float>(20.0 * std::exp(-r2 / (2.0 * 30.0 * 30.0)));
        }
    }
};

const Terrain terrain(Surface{}, std::make_shared<Dome>(), {std::make_shared<CraterLayer>()});
const Raster<float> heights = terrain.Evaluate();

    fill_samples(samples, spacing, threads) is the one method that makes heights. A sample block is either the cells of a grid or a list of points, so the same code serves whole grids and single queries and both give the same height at the same place. samples.positions() gives every position and samples.heights() is the array to fill, NaN where the source has no data. resolution_at(x, y) tells crater and boulder layers which features the source already resolves, so they add only the smaller ones. post_spacing_at(x, y) gives the spacing of the posts behind each height, measured or generated, which roughness estimates sample the source at.

    Layers¶

    A layer changes the heights beneath it. One whose height at a point depends only on the height there and the point implements apply_at in Python, or derives from FormulaLayer in C++, and is then evaluated over grids and at points like the built-in layers. Layers after it are laid over what it makes, so here craters fall on ridges.

    class Ridges(terraingen.Layer):
    """Ridges 2 m high and 40 m apart, running north."""

    def apply_at(self, height, x, y, context):
        return height + 2.0 * math.cos(2.0 * math.pi * x / 40.0)

craters = terraingen.CraterLayer()
terrain = terraingen.Terrain(source=terraingen.FlatSource(129, 129, 1.0), layers=[Ridges(), craters])
heights = terrain.evaluate()

    // Ridges 2 m high and 40 m apart, running north.
class Ridges final : public FormulaLayer {
  protected:
    float HeightAt(float height, double x, double /*y*/,
                   const LayerContext& /*context*/) const override {
        return height + static_cast<float>(2.0 * std::cos(2.0 * kPi * x / 40.0));
    }
};

const Terrain terrain(Surface{}, std::make_shared<FlatSource>(129, 129, 1.0),
                      {std::make_shared<Ridges>(), std::make_shared<CraterLayer>()});
const Raster<float> heights = terrain.Evaluate();

    A quick change needs no class at all. FunctionLayer turns a function of the point, the sample spacing and the height so far into a layer, a Python function or a C++ lambda.

    A layer that needs more than one point at a time, such as a filter over its neighbors, implements apply(heights, context) in Python, changing a raster in place, or ApplySamples on Layer in C++.

    Upsamplers¶

    An upsampler decides a source's heights between its posts and below their spacing, as cubic interpolation or diamond-square refinement do. Registered under a name, configurations use it like the built-in ones, as a source's "upsampling", so a custom part can be chosen from JSON without changing any code that reads the configuration. Here it holds the nearest post's height, rounded down to 2 m terraces.

    class Terraces(terraingen.Upsampler):
    """The nearest post's height, rounded down to a multiple of 2 m, which makes flat terraces."""

    def fill_samples(self, posts, samples, spacing, threads):
        heights = samples.heights()
        for i, (x, y) in enumerate(samples.positions()):
            col, row = posts.transform().world_to_pixel(x, y)
            height = posts.read(math.floor(col), math.floor(row), 1, 1)[0, 0]
            heights[i] = 2.0 * math.floor(height / 2.0)

    def reach(self):
        return 1

terraingen.register_upsampler("terraces", Terraces)  # Terraces(**settings) makes one
config = terraingen.TerrainGenConfig.from_dict(
    {
        "schema_version": 1,
        "source": {
            "type": "synthetic",
            "pixel_size_m": 4,
            "stack": [{"wavelength_m": 120, "amplitude_m": 8, "octaves": 3}],
            "upsampling": "terraces",
        },
    }
)
terrain = terraingen.build_terrain(config)
grid = terraingen.RasterGrid.centered((0.0, 0.0), (128.0, 128.0), 1.0)
heights = terrain.evaluate(grid)

    class Terraces final : public Upsampler {
  public:
    int Reach() const override {
        return 1;
    }

  protected:
    void FillSamples(const PostLattice& posts, SampleBlock& samples, double /*spacing*/,
                     unsigned /*threads*/) const override {
        const GeoTransform transform = posts.Transform();
        for (std::size_t i = 0; i < samples.Size(); ++i) {
            const Vec2d p = samples.Position(i);
            const Vec2d pixel = transform.WorldToPixel(p.x, p.y);
            float height = 0.0f;
            posts.Read(static_cast<std::int64_t>(std::floor(pixel.x)),
                       static_cast<std::int64_t>(std::floor(pixel.y)), 1, 1, {&height, 1});
            samples.Height(i) = 2.0f * std::floor(height / 2.0f);
        }
    }
};

RegisterUpsampler("terraces",
                  [](const std::string& /*settings*/) { return std::make_shared<Terraces>(); });
const TerrainGenConfig config = ParseConfig(R"({
    "schema_version": 1,
    "source": {"type": "synthetic", "pixel_size_m": 4, "upsampling": "terraces",
               "stack": [{"wavelength_m": 120, "amplitude_m": 8, "octaves": 3}]}
})");
const RasterGrid grid = RasterGrid::Centered({0.0, 0.0}, {128.0, 128.0}, 1.0);
const Raster<float> heights = BuildTerrain(config).Evaluate(grid);

    reach() is how many posts either side of a point the upsampler reads, so tiles read enough of their neighbors to join seamlessly. Settings given in the configuration are passed to the factory, in Python as keyword arguments and in C++ as JSON text.

    Size-frequency distributions¶

    A size-frequency distribution gives how many craters or boulders there are of each size, as the cumulative count N(>= D) per square meter. Only the cumulative count is needed, since the incremental count and the inverse used to draw diameters are derived from it. Any crater layer or boulder layer takes it in place of a published distribution.

    class SteepPowerLaw(terraingen.SizeFrequencyDistribution):
    """N(>= D) = 0.2 D^-2.5 craters per square meter, D in meters, from 1 m to 100 km."""

    def __init__(self):
        super().__init__(terraingen.SfdKind.DENSITY, 1.0, 1e5)

    def cumulative_at(self, diameter):
        return 0.2 * diameter**-2.5

models = terraingen.CraterModels(
    SteepPowerLaw(),
    terraingen.FreshAges(),
    terraingen.NoDegradation(terraingen.lunar_fresh_crater_morphometry),
    terraingen.FassettThomsonProfile(),
)
options = terraingen.CraterLayerOptions(
    seed=3, generation=terraingen.CraterGenerationOptions(min_diameter=2.0, max_diameter=60.0)
)
table = terraingen.CraterLayer(models, options).craters((-100.0, -100.0, 100.0, 100.0))

    // N(>= D) = 0.2 D^-2.5 craters per square meter, D in meters, from 1 m to 100 km.
class SteepPowerLaw final : public SizeFrequencyDistribution {
  public:
    SteepPowerLaw() : SizeFrequencyDistribution(SfdKind::Density, {1.0, 1e5}) {}

  protected:
    double CumulativeAt(double diameter) const override {
        return 0.2 * std::pow(diameter, -2.5);
    }
};

const CraterModels models{std::make_shared<SteepPowerLaw>(), std::make_shared<FreshAges>(),
                          std::make_shared<NoDegradation>(LunarFreshCraterMorphometry),
                          std::make_shared<FassettThomsonProfile>()};
CraterLayerOptions options;
options.seed = 3;
options.generation.minDiameter = 2.0;
options.generation.maxDiameter = 60.0;
const CraterList craters = CraterLayer(models, options).Craters({-100.0, -100.0, 100.0, 100.0});

    A crater layer is made of four models. They are this distribution, the ages, the degradation and the profile. The next three sections replace the other three.

    Crater age models¶

    A crater age model gives how long craters of each size stay visible. It draws each crater's age within that lifetime, uniformly unless you say otherwise. Freshness degradation wears craters over the same lifetimes, so the ages also set how worn each crater is. Here small craters are erased quickly and large ones last, so small craters are always young.

    class ErasedBySize(terraingen.CraterAgeModel):
    """Craters last 10 Myr per meter of diameter, up to 3.5 Gyr, so small ones are always young."""

    def lifetime_at(self, diameter):
        return min(0.01 * diameter, 3.5)

    def sample_age_at(self, random, diameter, lifetime_gyr):
        return lifetime_gyr * random.next_double()  # optional; uniform when left out

ages = ErasedBySize()
models = terraingen.CraterModels(
    terraingen.PowerLawSfd(0.05, 2.0),
    ages,
    terraingen.FreshnessDegradation(ages, terraingen.lunar_fresh_crater_morphometry),
    terraingen.MartinParkesDunstanProfile(),
)
options = terraingen.CraterLayerOptions(
    seed=4, generation=terraingen.CraterGenerationOptions(min_diameter=4.0, max_diameter=200.0)
)
table = terraingen.CraterLayer(models, options).craters(REGION)  # with each crater's age

    // Craters last 10 Myr per meter of diameter, up to 3.5 Gyr, so small ones are always young.
class ErasedBySize final : public CraterAgeModel {
  protected:
    double LifetimeAt(double diameter) const override {
        return std::min(0.01 * diameter, 3.5);
    }

    double SampleAgeAt(RandomStream& random, double /*diameter*/,
                       double lifetimeGyr) const override {
        return lifetimeGyr * random.NextDouble();
    }
};

const auto ages = std::make_shared<ErasedBySize>();
const CraterModels models{
    std::make_shared<PowerLawSfd>(0.05, 2.0), ages,
    std::make_shared<FreshnessDegradation>(ages, LunarFreshCraterMorphometry),
    std::make_shared<MartinParkesDunstanProfile>()};
CraterLayerOptions options;
options.seed = 4;
options.generation.minDiameter = 4.0;
options.generation.maxDiameter = 200.0;
const CraterList craters = CraterLayer(models, options).Craters({-250.0, -250.0, 250.0, 250.0});

    Crater profiles¶

    A crater profile gives a crater's height by distance from its center, shaped by its current depth and rim height as fractions of its diameter, which the degradation model sets. It also says how many radii from the center it reaches, so the layer knows which craters touch a point. Here a straight-walled cone replaces the default bowl of Martin, Parkes and Dunstan.

    class ConeProfile(terraingen.CraterProfile):
    """A straight-walled cone to the rim, and a rim that falls off as the cube of distance."""

    def height(self, distance, diameter, state):
        x = distance / (0.5 * diameter)
        depth = state.current.depth_ratio * diameter
        rim = state.current.rim_height_ratio * diameter
        return rim - depth * (1.0 - x) if x <= 1.0 else rim * x**-3

    def reach_radii(self):
        return 2.0  # how far from the center it changes the ground, in radii

models = terraingen.CraterModels(
    terraingen.PowerLawSfd(0.05, 2.0),
    terraingen.FreshAges(),
    terraingen.NoDegradation(terraingen.lunar_fresh_crater_morphometry),
    ConeProfile(),
)
options = terraingen.CraterLayerOptions(
    seed=1, generation=terraingen.CraterGenerationOptions(min_diameter=6.0, max_diameter=60.0)
)
craters = terraingen.CraterLayer(models, options)
heights = terraingen.Terrain(source=terraingen.FlatSource(129, 129, 1.0), layers=[craters]).evaluate()

    // A straight-walled cone to the rim, and a rim that falls off as the cube of distance.
class ConeProfile final : public CraterProfile {
  public:
    double Height(double distance, double diameter, const CraterState& state) const override {
        const double x = distance / (0.5 * diameter);
        const double depth = state.current.depthRatio * diameter;
        const double rim = state.current.rimHeightRatio * diameter;
        return x <= 1.0 ? rim - depth * (1.0 - x) : rim / (x * x * x);
    }

    double ReachRadii() const override {
        return 2.0;
    }
};

const CraterModels models{std::make_shared<PowerLawSfd>(0.05, 2.0),
                          std::make_shared<FreshAges>(),
                          std::make_shared<NoDegradation>(LunarFreshCraterMorphometry),
                          std::make_shared<ConeProfile>()};
CraterLayerOptions options;
options.seed = 1;
options.generation.minDiameter = 6.0;
options.generation.maxDiameter = 60.0;
const Terrain terrain(Surface{}, std::make_shared<FlatSource>(129, 129, 1.0),
                      {std::make_shared<CraterLayer>(models, options)});
const Raster<float> heights = terrain.Evaluate();

    On the GPU a profile of your own is tabulated per crater, so craters shaped by it are still drawn by the crater kernel.

    Degradation models¶

    A degradation model gives each crater's depth and rim height, both fresh and now. It reads only the crater's diameter, age and ID. The profile shapes the crater to this state. Crater lists report it as each crater's depth ratio and freshness, so you can check it without evaluating any heights. Here craters lose half their depth and rim every Gyr.

    class ShallowWithAge(terraingen.DegradationModel):
    """Craters 0.2 times as deep as wide when fresh, losing half that depth every Gyr."""

    def state(self, crater):
        fresh = terraingen.CraterMorphometry(0.2, 0.04)
        share = 0.5**crater.age_gyr
        now = terraingen.CraterMorphometry(0.2 * share, 0.04 * share)
        return terraingen.CraterState(fresh, now, 0.0)

surface = terraingen.EquilibriumSurface(
    terraingen.extended_neukum_production_function(),
    terraingen.trask_equilibrium(),
    3.5,
    terraingen.neukum_lunar_chronology,
)
models = terraingen.CraterModels(
    surface.density(), surface.ages(), ShallowWithAge(), terraingen.MartinParkesDunstanProfile()
)
craters = terraingen.CraterLayer(models)
table = craters.craters((-100.0, -100.0, 100.0, 100.0))  # with each crater's depth ratio now

    // Craters 0.2 times as deep as wide when fresh, losing half that depth every Gyr.
class ShallowWithAge final : public DegradationModel {
  public:
    CraterState State(const Crater& crater) const override {
        const CraterMorphometry fresh{0.2, 0.04};
        const double share = std::pow(0.5, crater.ageGyr);
        return {fresh, {0.2 * share, 0.04 * share}, 0.0};
    }
};

const EquilibriumSurface surface{
    std::make_shared<SplicedSfd>(ExtendedNeukumProductionFunction()),
    std::make_shared<PowerLawSfd>(TraskEquilibrium()), 3.5, NeukumLunarChronology};
const CraterModels models{surface.Density(), surface.Ages(), std::make_shared<ShallowWithAge>(),
                          std::make_shared<MartinParkesDunstanProfile>()};
const CraterLayer craters(models);
const CraterFeatures listed = DescribeCraters(craters.Craters({-100.0, -100.0, 100.0, 100.0}),
                                              models.Shape());  // with each state

    Surface fields¶

    A surface field is a value that varies over the ground, read at any point. Crater and boulder layers take one as a density map. It scales their density point by point, or gives a count or covered share to match. The field also gives its largest value, which bounds how many features are drawn before thinning. Here a field clears craters from a landing pad and lets them back in around it.

    class LandingPad(terraingen.SurfaceField):
    """No craters within 60 m of the center, rising to the layer's own density at 100 m."""

    def value_at(self, x, y):
        return min(max((math.hypot(x, y) - 60.0) / 40.0, 0.0), 1.0)

    def max(self):
        return 1.0

density_map = terraingen.DensityMap()
density_map.field = LandingPad()
density_map.measure = terraingen.DensityMeasure.SCALE  # times the layer's own density
options = terraingen.CraterLayerOptions(
    seed=5, generation=terraingen.CraterGenerationOptions(min_diameter=4.0, max_diameter=40.0)
)
options.density_map = density_map
table = terraingen.CraterLayer(options=options).craters(REGION)

    // No craters within 60 m of the center, rising to the layer's own density at 100 m.
class LandingPad final : public SurfaceField {
  public:
    double ValueAt(double x, double y) const override {
        return std::clamp((std::hypot(x, y) - 60.0) / 40.0, 0.0, 1.0);
    }

    double Max() const override {
        return 1.0;
    }
};

DensityMap densityMap;
densityMap.field = std::make_shared<LandingPad>();
densityMap.measure = DensityMeasure::Scale;  // times the layer's own density
CraterLayerOptions options;
options.seed = 5;
options.generation.minDiameter = 4.0;
options.generation.maxDiameter = 40.0;
options.densityMap = densityMap;
const CraterLayer craters(DefaultCraterModels(), options);
const CraterList list = craters.Craters({-200.0, -200.0, 200.0, 200.0});

    A map read from a GeoTIFF needs no class. RasterField wraps a raster, as in Vary Crater Density With a Map.

    Albedo sources¶

    An albedo source gives the starting albedo. It defines its number of bands, 1 or 3, and the value at any point. It can be a map in a format of your own, an analytic pattern or another model's output. Albedo layers are laid over it as over a synthetic albedo. Here dark mare meets bright highlands along a winding contact, and a fresh crater's rays reach across it.

    class MareContact(terraingen.AlbedoSource):
    """Dark mare at 0.09 in the west and bright highlands at 0.16 in the east, along a winding
    contact about 40 m wide."""

    def bands(self):
        return 1

    def value_at(self, x, y, context):
        share = 0.5 * (1.0 + math.tanh((x - 20.0 * math.sin(y / 60.0)) / 20.0))
        return 0.09 + 0.07 * share

craters = terraingen.CraterLayer.manual([terraingen.Crater(70.0, -60.0, 60.0, age_gyr=0.0)])
rays = terraingen.CraterAlbedo(craters, terraingen.CraterAlbedoOptions(seed=2))
albedo = terraingen.Albedo(MareContact(), [rays])
grid = terraingen.RasterGrid.centered((0.0, 0.0), (400.0, 400.0), PIXEL)  # meters
(values,) = terraingen.evaluate_albedo(albedo, grid)

    // Dark mare at 0.09 in the west and bright highlands at 0.16 in the east, along a winding
// contact about 40 m wide.
class MareContact final : public AlbedoSource {
  public:
    std::size_t Bands() const override {
        return 1;
    }

    AlbedoSample ValueAt(double x, double y, const LayerContext& /*context*/) const override {
        const double share = 0.5 * (1.0 + std::tanh((x - 20.0 * std::sin(y / 60.0)) / 20.0));
        return {static_cast<float>(0.09 + 0.07 * share), 0.0f, 0.0f};
    }
};

CraterAlbedoOptions options;
options.seed = 2;
Albedo albedo;
albedo.source = std::make_shared<MareContact>();
albedo.layers = {std::make_shared<CraterAlbedo>(
    CraterLayer::Manual({ManualCrater(70.0, -60.0, 60.0)}), options)};
const RasterGrid grid = RasterGrid::Centered({0.0, 0.0}, {400.0, 400.0}, 2.0);  // meters
const std::vector<Raster<float>> bands = EvaluateAlbedo(albedo, grid, {});

    Crater rays brighten by optical maturity, which leaves reflectance below 0.08 unchanged. Keep a source at or above that where craters should brighten it.

    Albedo layers¶

    An albedo layer changes the albedo beneath it, one point at a time, from the value there and the point. It is laid over any albedo source with the built-in layers, in order. Here two rover wheel tracks along a winding path darken a synthetic albedo.

    class RoverTracks(terraingen.AlbedoLayer):
    """Two wheel tracks 0.4 m wide and 1.8 m apart along a winding path, 20 percent darker."""

    def apply_at(self, value, bands, x, y, context):
        middle = 3.0 * math.sin(x / 8.0)
        if any(abs(y - middle - wheel) < 0.2 for wheel in (-0.9, 0.9)):
            return [band * 0.8 for band in value]
        return value

soil = terraingen.Fractal(seed=1, wavelength=10.0, amplitude=0.2, octaves=5)
albedo = terraingen.Albedo(terraingen.SyntheticAlbedo(value=0.11, value_noise=[soil]), [RoverTracks()])
grid = terraingen.RasterGrid.centered((0.0, 0.0), (40.0, 16.0), PIXEL)  # meters
(values,) = terraingen.evaluate_albedo(albedo, grid)

    // Two wheel tracks 0.4 m wide and 1.8 m apart along a winding path, 20 percent darker.
class RoverTracks final : public AlbedoLayer {
  public:
    void ApplyAt(AlbedoSample& value, std::size_t bands, double x, double y,
                 const LayerContext& /*context*/) const override {
        const double middle = 3.0 * std::sin(x / 8.0);
        if (std::abs(y - middle + 0.9) < 0.2 || std::abs(y - middle - 0.9) < 0.2) {
            for (std::size_t band = 0; band < bands; ++band) {
                value[band] *= 0.8f;
            }
        }
    }
};

SyntheticAlbedoOptions options;
options.value = 0.11;
Fractal soil = Fractal::Fbm(1, 10.0, 0.2);
soil.octaves = 5;
options.valueNoise = {soil};
Albedo albedo;
albedo.source = std::make_shared<SyntheticAlbedo>(options);
albedo.layers = {std::make_shared<RoverTracks>()};
const RasterGrid grid = RasterGrid::Centered({0.0, 0.0}, {40.0, 16.0}, 0.05);  // meters
const std::vector<Raster<float>> bands = EvaluateAlbedo(albedo, grid, {});

    Rock meshes¶

    Boulder shapes can come from rock meshes, such as scans, in place of the procedural styles. Each boulder picks one by its shape seed, scaled to a long axis of 1 and then to its own size, and is posed, buried and settled like any other. read_mesh reads .obj, .gltf, .glb or .stl files, and a configuration names them as a boulder layer's shape_files. Here an octahedron stands in for a scanned rock.

    # An octahedron stands in for a scanned rock; terraingen.read_mesh reads .obj, .gltf, .glb or .stl.
corners = np.array([[1, 0, 0], [-1, 0, 0], [0, 0.7, 0], [0, -0.7, 0], [0, 0, 0.5], [0, 0, -0.5]], float)
faces = np.array([[0, 2, 4], [2, 1, 4], [1, 3, 4], [3, 0, 4], [2, 0, 5], [1, 2, 5], [3, 1, 5], [0, 3, 5]])
rock = terraingen.SceneMesh(terraingen.TriangleMesh(corners, faces))

shapes = terraingen.BoulderShapeOptions()
shapes.library = [rock]  # each boulder picks one of these by its shape seed
shape = terraingen.generate_boulder_shape(7, shapes)  # scaled to a long axis of 1
shape.mesh.write(output_folder / "rock.obj")

    TriangleMesh octahedron;
octahedron.positions = {{1, 0, 0},    {-1, 0, 0},  {0, 0.7, 0},
                        {0, -0.7, 0}, {0, 0, 0.5}, {0, 0, -0.5}};
octahedron.triangles = {{0, 2, 4}, {2, 1, 4}, {1, 3, 4}, {3, 0, 4},
                        {2, 0, 5}, {1, 2, 5}, {3, 1, 5}, {0, 3, 5}};

BoulderShapeOptions shapes;
shapes.library = {std::make_shared<const SceneMesh>(SceneMesh{octahedron, {}, {}})};
const BoulderShape shape = GenerateBoulderShape(7, shapes);  // scaled to a long axis of 1
WriteMesh(path, shape.mesh);

    Procedural shapes can be customized too, without meshes. A boulder style names the solid a shape starts from and the ranges of its axes, fractures, noise and worn edges, as in Design a Boulder Style of Your Own.

    Rules every part follows¶

    • Deterministic. A part gives the same answer for the same input every time. Anything random is drawn from a seed or from the crater's or boulder's ID, never from a shared generator, so the same seed gives the same terrain on any grid, tile or thread count.
    • A function of position. A point gets the same height as a grid cell centered there, so terrains can be evaluated in tiles that join without seams, or queried at single points.
    • Thread-safe. Parts are called from every evaluation thread at once, so they must not change shared state.
    • Python or C++. Python parts are convenient for trying ideas, but they are called for every sample and Python calls take turns on the GIL, so terrains with them gain little from more threads. A C++ part runs on every thread at full speed, and is the way to go once an idea works.
